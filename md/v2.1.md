Everything below is on `main` after the v2.0 tag.

For the forward roadmap (Parts 5–11) see `update-plan.md`.

## New features

### Player name

New `player.js` + `NamePromptScene`. First launch boots into the prompt;
after that straight to the menu, so nobody is asked twice. Default `PLAYER`,
14 characters max, editable from Settings.

Sanitiser strips control characters and angle brackets, collapses whitespace,
and caps length. Verified: `<script>x</script>` → `scriptx/script`,
`  A   B  ` → `A B`, 26 chars → 14.

### Cloud leaderboard

New `LeaderboardScene`, button under the medal on the menu. Two tabs —
HIGH SCORE and TROPHIES — with drag and wheel scrolling, gold/silver/bronze
rank colours, and zebra rows.

Backed by Firestore with **anonymous auth**, so there is no login wall. Writes
only fire when a score or trophy count is *beaten*, capped at 5 per session, so
replaying the same run writes nothing.

**`firestore.rules` is the actual security control.** The Firebase config ships
in the bundle and is readable by anyone — it is a project address, not a
password. The rules allow public reads, restrict writes to the caller's own
`request.auth.uid` document, whitelist fields, cap value ranges, and cap the
name at 14 characters.

Deliberately degrades rather than blocks: every network path has a timeout, and
a failure leaves the board empty instead of leaving a spinner on the menu.

Verified live against the deployed rules — the board reads back real rows:
`YASSIN / 412 / 10 trophies` and `yassin / 51 / 0`.

### Two new balls — 14 total

| Ball | Price | Ability |
|---|---|---|
| **Revive Ball** | $10,000 | Saves you once. On a miss the ball bounces back and play continues from the same score. |
| **Money Ball** | $24,500 | Earns **$5 per score** instead of $3 |

Revive Ball shows `REVIVE: 1` at top centre for the whole run, flips to
`REVIVE: 0` in grey the moment it is spent, and a green flash confirms it.
Verified: first miss consumed the charge and bounced the ball back to x=306 with
`gameOver: false`; second miss ended the run. No infinite lives.

## Bug fixes

### Shop page reset after buying or equipping

`handleBallPurchase()` calls `scene.restart()` to refresh the cards. The restart
rebuilt `this.page = 0`, so buying or equipping on page 2 jumped you back to page
1 without touching PREV/NEXT. Page now persists in `sessionStorage`
(`gdShopPage`) — `sessionStorage` not `localStorage` so leaving the shop and
returning later starts at page 1 again.

### Defeat screen reported zero earnings

`triggerDefeat()` passed `moneyEarned: 0` to the defeat screen. Money is banked
match by match, so a player who won three rounds then lost was told they had
earned nothing. The defeat path now reads the real `tournamentProgress` and
shows Matches Won, Total Deflects and Money Earned, plus a "No trophy prize this
time" line so the absent prize does not look like a bug.

### Grass drew over the goal explosion

Grass was at depth 11, above the goal (10) and above the explosion particles —
so the win feedback was hidden behind a decorative strip. Now depth −2 in both
`GameScene` and `TournamentGameScene`.

### Name field could not be typed on a phone

The real DOM input was `opacity:0; pointer-events:none`, so a tap never landed on
it and **no keyboard would ever appear on mobile**. The Phaser text is now
`setInteractive()` and its `pointerdown` focuses the hidden input — a user
gesture, which is what mobile browsers require before opening the keyboard.

### Loading screen ignored the game area

It covered the whole window and stayed axis-aligned while the game rotated 90°
on a phone, so the spinner appeared sideways outside the play area. `layout.js`
now owns its size, position and rotation, and it tracks the canvas exactly.
Verified: 800×450 against an 800×886 viewport, matching the canvas.

### Leaderboard rows overhung the panel

The right-aligned score column sat at x=1076 with the panel edge at 1070, and
rows ran past the panel bottom. Values moved to 1054 and the scroll range
tightened to 238–566 inside the 200–600 panel.

### Leaderboard scroll ran past the end

The row offset was *added* instead of subtracted, so scrolling down pushed every
row below the panel — with 40 test rows the bottom of the list rendered zero
rows and the worst-ranked players were invisible. Fixed; verified rows render at
top, middle and bottom.

### Loading/refresh crash on the Revive Ball

`createReviveCounter()` guarded with `if (this.reviveText) return;`. On a scene
restart that reference pointed at a *destroyed* Text whose canvas is null, so
`setText()` threw `Cannot read properties of null (reading 'cut')`. The guard
now checks the object is actually live.

### Revive charge leaked into every other ball

Worse than the crash and found while verifying it. The charge was set via a
`startRevives` field with the assignment *after* the switch, and
`loadBallAbilities()` never cleared it — so it survived across scene
constructions and **all 14 balls were born with a free revive**. Now assigned
directly inside the `revive` case. A full sweep confirms only Revive Ball has
one charge.

## Anti-autoclicker

One deflect per inbound pass, in both `GameScene` and `TournamentGameScene`.
`deflectLock` is set immediately before `onBallClick()` and cleared in `update()`
once the ball's x-velocity goes positive. Verified: five taps fired at a ball
inside the hitbox produce exactly **1** deflect in either scene, and the next
inbound pass deflects normally.

**Limit, stated plainly:** this is not a security control. The pre-existing
guards already rejected most repeat taps; the lock closes the narrow window
where a second event arrives before the velocity update lands. Anyone can still
edit `localStorage` or call `onBallClick()` from the console.
